# Luria.app Redesign

**Source:** redesign_20260623110817
**Date:** Jun 23, 2026

## Overview

This document presents a comprehensive redesign of **Luria.app** (by brainworkup™), a neuropsychological assessment and report-writing platform. The redesign covers 10 pages of UI mockups, workflow documentation, and technical infrastructure — spanning desktop and mobile views, AI-assisted clinical reasoning, and [[concepts/local-llm-inference|local LLM infrastructure]].

## Application Workspace Structure

Luria is organized into a consistent sidebar navigation with three sections:

- **Home:** Report Workspace (`⌘1`)
- **Workspace:** Patient Intake (`⌘2`), Clinical Office (`⌘3`), Console & Synthesis (`⌘4`)
- **Tools:** Visuomotor Sketchpad (`⌘5`), Cognitive Map (`⌘6`), Report Builder (`⌘7`)

Each session is tied to an **Active Case-File** (demo patient: Biggie Smalls, 7y, ADHD & dysgraphia).

## Pages & Key Features

### Page 01: Report Workspace
The dashboard hub showing all active dossiers, patient header, a 5-step **Progress Tracker** (Intake → Documents → Cognitive Map → Synthesis → Report), and live neurocognitive/neurobehavioral score tables. A **Synthesis Panel** surfaces AI-generated pattern impressions in real time.

Demo scores for Biggie Smalls:
| Domain | Score | Status |
|---|---|---|
| General Cognitive | 96 | Average |
| Academic Skills | 78 | Clinical Concern |
| Memory | 88 | Borderline |
| Attention/Executive | 76 | Clinical Concern |
| ADHD/Exec (T-score) | T72 | Elevated |

### Page 02: Patient Intake
Structured history capture with auto-tagging via the **Λ (Lambda) AI assistant**. Referral text is parsed into discrete clinical concerns (`Inattention`, `Graphomotor`, `Academic underperformance`, `r/o ADHD`, `r/o Dysgraphia`). Developmental and medical history is organized in a flagged table. The AI assistant identifies gaps (e.g., missing prior psychoeducational testing) and suggests follow-up items. This implements a [[concepts/staged-clinical-intake]] workflow feeding into [[concepts/neurodevelopmental-clinical-intake]].

### Page 03: Document Ingestion
PDF and file ingestion using markitdown (PDF → Markdown conversion), shown via screenshots of the processing pipeline. This relates to the [[concepts/pdf-data-extraction]] and [[concepts/clinical-pdf-assessment]] capabilities in the broader pipeline.

### Page 04: Clinical Office (Documents)
Indexed source documents with RAG-powered fact extraction (24 chunks embedded). Each extracted fact is linked to its source page. Status indicators: `INDEXED`, `PROCESSING`, `NOT ON FILE`. Facts pre-fill the report background section. The approach uses [[concepts/retrieval-augmented-generation]] and [[concepts/rag-chunking]] to ground clinical claims in source documents.

### Page 05: Console & Synthesis
The core AI reasoning interface — described as "a clinical copilot you argue with." The clinician poses diagnostic questions; **Λ Luria** responds with grounded multi-source reasoning, numbered citations mapped to an Evidence Rail. Example exchange:
- *Question:* Is inattention primary ADHD or secondary to dysgraphia/frustration?
- *Luria's answer:* Primary ADHD, citing cross-setting Conners-4 elevations, dissociation from output scores, and onset history predating writing demands.

Actions: `[Add to Synthesis]`, `[Draft this section]`, `[Show reasoning]`. This is the primary [[concepts/clinical-ai-reasoning]] interface and relates to [[concepts/neuropsychological-synthesis]].

### Page 06: Visuomotor Sketchpad
A drawing/annotation tool available in Light and Dark themes — used for graphomotor assessment tasks (e.g., Beery VMI). Relevant to [[concepts/dysgraphia]] evaluation workflows.

### Page 07: Cognitive Map (Amber Theme)
A constellation visualization of 13 [[concepts/cognitive-domains]], sized by test breadth and colored by severity. The Amber theme is designed as a "dark, single-purpose room" for profile reading at a glance. AI auto-detects co-varying clusters:
> **Frontal-graphomotor cluster** — Attention, executive control, and motor output co-vary and are jointly depressed while verbal reasoning is spared — the ADHD-Inattentive + dysgraphia signature.

This pattern detection connects [[concepts/adhd-clinical-features]], [[concepts/executive-function-deficits]], and [[concepts/dysgraphia]] into a unified clinical impression.

### Page 08: Report Builder
Section-by-section report drafting with AI assistance. Controls include voice tone (Clinical / Balanced / Parent), reading level slider (Grade 8 ↔ Professional), and insertable elements (score table, domain figure, DSM-5 criteria). 4 of 6 sections finalized in the demo. This implements [[concepts/modular-report-architecture]] and [[concepts/narrative-report-generation]] with [[concepts/clinical-narrative-generation]].

### Page 09: LLM Infrastructure & Local Inference
Three-tab technical documentation:

**Architecture Overview:**
- UI components: `IntakeDossier.tsx`, `ReportJobStatus`, `ConsoleChat`
- Orchestration: `redactPhi()` PHI guard, `reportJobs.ts`, `llmAbortContext` (AsyncLocalStorage for cancellation)
- Agents: `agentRunner.ts` → section agents (`nseCodSummary`, `ROCFT`, report-section agents)
- Client: `LocalFallbackLLMClient` with `pickProvider()`

The agent orchestration implements a [[concepts/multi-agent-orchestration]] pattern with [[concepts/subagent-architecture]], and the PHI guard connects to [[concepts/phi-deidentification-pipeline]] and [[concepts/phi-data-handling]].

**Fallback Chain (priority order):**
1. **oMLX** — local OpenAI-compatible API (PHI-safe) — see [[concepts/omlx-server]]
2. **vMLX** — local Responses API (PHI-safe)
3. **Ollama** — local native API (PHI-safe)
4. **Cloud** — remote fallback, non-PHI only (blocked by `restrictToPreferredProviders: true`)

This implements a [[concepts/fallback-strategy]] with [[concepts/llm-provider-abstraction]] and [[concepts/local-first-architecture]]. The `restrictToPreferredProviders` flag enforces [[concepts/privacy-first-software]] principles and [[concepts/clinical-data-privacy]].

**Data Flow (3 paths):**
- A: Intake → encrypted SQLite → `redactPhi()` → local LLM → Clinical Summary
- B: UI → report job → `runReportJob()` → section agents → fallback chain
- C: AgentContext → section agent → LLM inference → structured report section

This data flow is part of the broader [[concepts/neuropsychological-assessment-pipeline]] and [[concepts/agent-pipeline-state-management]].

### Page 10: Knowledge Base (KB) — OpenKB Integration
A proposed but **not yet implemented** backend feature: integrating a knowledge base layer on the backend using OpenKB. OpenKB compiles documents into a persistent, interlinked wiki using LLMs + PageIndex for vectorless long-document retrieval.

**Key distinctions from traditional [[concepts/retrieval-augmented-generation]]:**
- Knowledge is compiled once and accumulated, not re-derived per query
- Cross-references and contradictions are pre-resolved
- Supports short docs (markitdown → full LLM read) and long PDFs (PageIndex tree index)
- Relates to [[concepts/knowledge-base-architecture]] and [[concepts/knowledge-continuity]]

**OpenKB Generators:**
- `openkb query` — grounded Q&A with citations
- `openkb chat` — multi-turn session with slash commands
- `openkb skill new` — compiles wiki subset into an Anthropic Skill (portable, installable by Claude Code, Codex CLI, Gemini CLI, Cursor); see [[concepts/luria-skills]] and [[concepts/skills-modules]]
- `openkb skill eval` / `validate` / `history` / `rollback` — quality gates and versioning; relates to [[concepts/llm-evaluation]]

**Tech stack:** markitdown, OpenAI Agents SDK, LiteLLM, Click, watchdog

## Key Clinical Themes

- **PHI-first local inference:** All patient data stays on-device; cloud is a PHI-blocked last resort — see [[concepts/phi-data-handling]] and [[concepts/clinical-data-privacy]]
- **Grounded AI reasoning:** Every AI claim is tied to a numbered source citation — see [[concepts/clinical-ai-reasoning]]
- **Profile pattern detection:** AI identifies domain clusters and named syndromes (e.g., ADHD-I + dysgraphia) — see [[concepts/neuropsychological-synthesis]]
- **Progressive workflow:** Linear 5-step pipeline from intake to final report, with AI assistance at each stage — see [[concepts/neuropsychological-assessment-workflow]]
- **Multi-modal themes:** Light, Dark, and Amber color modes serve different clinical use cases — relates to [[concepts/brand-theming]]
