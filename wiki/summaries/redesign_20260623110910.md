# Luria.app Redesign — Summary

*Source: redesign_20260623110910 · Jun 23, 2026*

## Overview

Luria (by brainworkup™) is a clinical neuropsychological assessment platform redesigned around an AI copilot workflow. The redesign document covers 10 pages of UI mockups and technical architecture, illustrating a complete case — a 7-year-old male ("Biggie Smalls") evaluated for ADHD and dysgraphia — flowing through every module of the app.

---

## Application Modules

### 1. Report Workspace (`⌘1`)
The dashboard showing all active dossiers. Displays:
- **Neurocognitive scores** (4/7 domains evaluated) with status indicators (Evaluated / Borderline / Clinical Concern)
- **Neurobehavioral scores** (ADHD/Executive T72 — Elevated)
- A **live Synthesis Panel** that narrates the clinical pattern in real time
- Progress tracker: Intake → Documents → Cognitive Map → Synthesis → Report
- Desktop and mobile companion views

**Sample scores for Biggie Smalls:**
| Domain | Score | Status |
|---|---|---|
| General Cognitive Ability | 96 | Average |
| Academic Skills | 78 | Clinical Concern |
| Memory | 88 | Borderline |
| Attention / Executive | 76 | Clinical Concern |

### 2. Patient Intake (`⌘2`)
Structured history captured once and reused everywhere:
- Demographics, referral question, developmental/medical history
- Auto-structured referral parsing with AI tags (`Inattention`, `Graphomotor`, `r/o ADHD`, etc.)
- AI intake assistant flags missing data (e.g., no prior psychoeducational testing) and suggests follow-ups

See also: [[concepts/neurodevelopmental-clinical-intake]], [[concepts/staged-clinical-intake]]

### 3. Document Ingestion (Page 3)
- PDF/file-to-Markdown conversion via markitdown
- Visual upload interface for clinical records

### 4. Clinical Office / Documents (`⌘3`)
- **RAG-backed** document index: 24 chunks embedded, 3 indexed + 1 processing
- Source types: Clinical Interview, Prior Medical Records, School Records/IEP, Prior Testing
- Facts extracted and linked to source pages (e.g., "Expressive speech delay treated age 3-4 ↳ Medical Records · p.3")
- Grounded facts pre-fill the report background section

See also: [[concepts/retrieval-augmented-generation]], [[concepts/clinical-data-management]]

### 5. Console & Synthesis (`⌘4`)
The flagship [[concepts/clinical-ai-copilot]] experience:
- Conversational reasoning over the case with **source citations**
- Clinician asks: *"Is the inattention primary ADHD, or secondary to dysgraphia?"*
- Luria responds with three evidence lines (cross-setting Conners-4, NEPSY-II dissociation, interview history), numbered citations, and a **provisional impression**
- Actions: [Add to Synthesis] [Draft this section] [Show reasoning]
- Evidence rail lists each cited source with scores

See also: [[concepts/clinical-ai-reasoning]], [[concepts/neuropsychological-synthesis]]

### 6. Visuomotor Sketchpad (`⌘5`)
- Drawing/graphomotor capture tool
- Available in Light and Dark themes

### 7. Cognitive Map (`⌘6`) — Amber Theme
- 13 neurocognitive domains displayed as a "Cognitive Constellation" (node size = test breadth, color = severity)
- AI pattern detection: "Frontal-graphomotor cluster" — attention, executive control, and motor output co-vary and are jointly depressed while verbal reasoning is spared
- Named pattern: **ADHD-Inattentive + dysgraphia signature**
- Convergence score: 4/4; Spared strengths: Verbal 102, Reasoning 96

See also: [[concepts/cognitive-domains]], [[concepts/dysgraphia]], [[concepts/adhd-clinical-features]]

### 8. Report Builder (`⌘7`)
- 6-section report structure; 4/6 finalized
- AI drafts from 6 tests & 3 sources with citations enabled
- Controls: voice (Clinical / Balanced / Parent), reading level (Gr 8 to Professional), section inserts (score tables, domain figures, DSM-5 criteria)
- Export to PDF

See also: [[concepts/narrative-report-generation]], [[concepts/clinical-report-structure]], [[concepts/modular-report-architecture]]

## Technical Architecture (Pages 9–10)

### LLM Infrastructure & Local Inference

Three-tab architecture view:

**Tab 1 — Connectivity Map:**
- UI layer: `IntakeDossier.tsx`, `ReportJobStatus`, `ConsoleChat`
- Orchestration: `reportJobs.ts` (createReportJob / runReportJob), PHI guard via `redactPhi()`
- Agent layer: `agentRunner.ts` → section agents (nseCodSummary, ROCFT, report-section agents)
- LLM Client: `LocalFallbackLLMClient` with `pickProvider()`

See also: [[concepts/agent-pipeline-state-management]], [[concepts/phi-deidentification-pipeline]], [[concepts/multi-agent-orchestration]]

**Tab 2 — Fallback Chain (privacy-first):**
| Priority | Provider | PHI-safe? |
|---|---|---|
| 1 | oMLX | ✓ Local |
| 2 | vMLX (Responses API) | ✓ Local |
| 3 | Ollama | ✓ Local |
| 4 | Cloud | ✗ Non-PHI only |

- `restrictToPreferredProviders: true` enforces local-only gate for PHI
- `llmAbortContext` uses `AsyncLocalStorage` to cancel mid-fallback

See also: [[concepts/local-llm-inference]], [[concepts/fallback-strategy]], [[concepts/llm-provider-abstraction]], [[concepts/local-first-architecture]], [[concepts/phi-data-handling]], [[concepts/omlx-server]]

**Tab 3 — Data Flow:**
- Intake → encrypted SQLite → `redactPhi()` → local LLM → clinical summary
- Report job: POST → createReportJob → runReportJob → agentRunner → section agents → fallback chain
- Agent context carries raw clinical data and patient scores

See also: [[concepts/neuropsychological-assessment-pipeline]], [[concepts/pii-redaction-pipelines]]

## Knowledge Base Integration (Page 10 — Not Yet in App)

Page 10 describes a planned [[concepts/knowledge-base-architecture]] integration on the backend, referencing OpenKB — an open-source system that compiles documents into a persistent wiki using LLMs + PageIndex for vectorless long-document retrieval.

### Core Distinction: Compiled vs. Re-derived Knowledge
- **Traditional [[concepts/retrieval-augmented-generation]]**: re-discovers knowledge from scratch on every query
- **OpenKB**: compiles knowledge once into a persistent wiki; cross-references pre-exist; contradictions are flagged; synthesis reflects everything consumed

See also: [[concepts/knowledge-continuity]], [[concepts/knowledge-capture]]

### Document Handling
| | Short docs | Long PDFs (≥20 pages) |
|---|---|---|
| Convert | markitdown → Markdown | PageIndex → tree index + summaries |
| LLM reads | Full text | Document trees |

See also: [[concepts/pdf-data-extraction]], [[concepts/docling-pdf-parsing]]

### Knowledge Compilation Steps
1. Generate summary page
2. Read existing concept/entity pages
3. Create/update concepts with cross-document synthesis
4. Create/update entity pages
5. Update index and log

### Generators
- `openkb query` — grounded single-question answers
- `openkb chat` — multi-turn session with history (`--resume`, `/skill new`, `/save`)
- `openkb skill new <name>` — distills wiki into an Anthropic Skill (portable folder for Claude Code, Codex CLI, Gemini CLI, Cursor)

See also: [[concepts/luria-skills]], [[concepts/skills-modules]]

### Skill Factory
Produces a redistributable skill folder:
```
output/skills/<name>/
├── SKILL.md
├── references/
└── (scripts/)
```
With quality gates: `skill validate`, `skill eval`, `skill history`, `skill rollback`.

### Stack
- **markitdown** — file-to-markdown conversion
- **OpenAI Agents SDK** + **LiteLLM** — multi-provider LLM gateway
- **PageIndex** — vectorless long-document retrieval
- **Click** + **watchdog** — CLI and filesystem monitoring

See also: [[concepts/openai-compatible-api]], [[concepts/mlx-framework]]
